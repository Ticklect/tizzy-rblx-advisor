# Compact public case-study library

Paraphrased patterns only. No transcript reproduction.

## Build a Base and Steal — growth/retention case study
Observed public lessons:
- evergreen building demand plus stealing/PvP gap;
- simple loop with depth from PvP + building;
- unsolved sessions because humans create variation;
- collection + player-built base create emotional investment;
- co-op/private play supports social flywheel;
- repeated tutorial experiments;
- title promise delivered early;
- threat signaled through action rather than walls of text;
- economy nerfs when progression was consumed too quickly;
- smaller map improved pace/interaction;
- center-space level design enabled juking/events;
- aspirational rare items teased early;
- monetization changed after observing timing/psychology.

Use when: user has a build/steal/PvP/collection/social game or asks why simple games can retain deeply.

## Hack a Business — optimization/monetization/packaging case study
Observed public lessons:
- title/core-fantasy reframing improved ad CTR in a public example;
- product sales and player behavior drove monetization hypotheses;
- AFK theft pain led to protection product;
- repeat-spend consumables tested;
- multiple purchase pathways improved cash sales;
- world placement near foot traffic used as merchandising;
- monetization checked against engagement/economy;
- cinematic/onboarding experiment publicly associated with bounce improvement.

Use when: user has decent core experience but weak packaging/monetization or a tycoon/incremental economy.

## Farmer Die — learning/failure case study
Observed public lessons:
- could achieve a modest durable audience while still having weak retention;
- public creator repeatedly used it to explain that broad green stats or initial traffic do not guarantee sustained recommendation traffic;
- later treated weak retention as a lesson, not proof the algorithm was unfair.

Use when: user blames distribution while retention is weak.

## Alien Ranch -> Farmer Die market-research example
Observed public reasoning:
- smaller game with proven loop and visible demand;
- weak update cadence/bugs created an execution gap;
- study loop/progression/feedback deeply;
- add meaningful mechanics/progression instead of a cosmetic reskin.

Use when: user is hunting for a first viable game idea rather than a 100K-CCU moonshot.

## Algorithm explainer series
Observed public reasoning:
- official documentation first;
- separate cold/paid traffic from Home traffic;
- benchmark against similar-player experiences as a diagnostic, not a ranking input;
- weak metrics require product iteration, not blind ad spend;
- model discovery as a funnel;
- segment by source/device;
- admit uncertainty when platform changes are fresh.

Use when: user repeats rumors or wants to know why recommendations changed.

## Viral-design / game-design decomposition videos
Observed public reasoning:
- clickable/core fantasy;
- onboarding creates emotional investment, not just completion;
- socialization/word-of-mouth;
- simple mechanic with depth;
- clippability/community;
- game building blocks: fantasy, unique mechanic, loop, RNG, level design, tension, progression, collection;
- innovate where it changes how players feel/decide.

Use when: user asks whether an idea is good or how to differentiate it.
